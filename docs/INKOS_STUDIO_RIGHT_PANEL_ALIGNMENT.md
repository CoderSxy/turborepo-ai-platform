# AI 小说创作右侧面板：InkOS Studio 对齐改版说明

> 目标读者：Cursor 执行者  
> 优先级：P1（不影响“写下一章”主路径，但显著影响工作台信息密度）  
> 参考：InkOS `packages/studio/src/components/chat/BookSidebar.tsx`、`components/sidebar/*`  
> 当前入口：`apps/web/features/studio/components/NovelBookPanel.tsx`

## 1. 问题与改版目标

### 截图所反映的差异

InkOS Studio 右栏遵循“**少量、可扫读、与当前创作直接相关**”的原则：

- 以章节、角色、核心文件、世界观等 4–5 个卡片构成主层级。
- 未展开的卡片只显示标题和箭头；展开后是简短内容或紧凑列表。
- 点击章节/核心文件后进入独立的 Artifact 阅读视图，而不是继续在右栏堆叠编辑控件。
- 写作执行过程主要在聊天区/短状态条中反馈，右栏不承担完整任务日志控制台。

### InkOS 收起卡片的真实内容参考（必须同时参考）

InkOS 的收起并不是把内容“藏起来就算完成”，而是先把信息按来源和用途分成固定的轻量卡片。当前 `BookSidebar` 在主面板中依次编排：`ProgressSection`、`ChaptersSection`、`CharacterSection`、`FoundationSection`、`SummarySection`；截图里的“章节 / 角色 / 核心文件 / 世界观 / 角色”正来自这些 section。

| InkOS 卡片 | 收起态应表达的含义 | 展开态真实内容 | 当前项目对应数据 | 当前项目改版后的落点 |
| --- | --- | --- | --- | --- |
| 执行（仅任务运行时） | 正在写作/审计/修订，不常驻空白卡片 | 固定步骤的完成/进行中状态：准备章节输入、撰写草稿、落盘、同步记忆等 | `runningTask`、聊天 `progress` parts、`StoredNovelTask` | **聊天任务卡为主**；右栏仅在运行时显示一行状态，不复制完整日志 |
| 章节 | 当前有哪些章节，可快速定位 | 章节号、标题、状态符号、字数；列表内部限高滚动；点击打开章节 Artifact | `chapterRows`、`StoredNovelChapter`、`activeChapterId` | `ChaptersSection`；收起只显示标题与数量/当前章，展开显示紧凑列表，点击进入章节详情 |
| 角色（CharacterSection） | 当前书有哪些角色资产 | 从 `character_matrix.md` 解析角色卡：名字、定位、标签、当前状态；单个角色可再展开 | `assets.characters`、`knowledgeAssets`、角色状态/关系资产 | `CharactersSection`；收起显示角色数量和当前章相关角色，展开最多 4 张紧凑状态卡，完整角色矩阵进入详情 |
| 核心文件 | 有哪些可作为创作事实来源的文件 | 仅列已存在文件：世界观设定、卷纲、叙事规则、状态卡、伏笔池、支线、感情线、角色矩阵；点击打开 Artifact | `assets.worldNotes`、`outline`、`settings`、`characters`、`knowledgeAssets`、`outlineNodes` | `CoreFilesSection`；收起显示“已加载 N 项”，展开是文件链接列表，点击进入详情，不内嵌全文 |
| 世界观（SummarySection） | 当前故事的核心世界规则 | 从 `story_bible.md` 取“世界观”章节的首段，使用 Markdown 轻量渲染 | `project.world`、`assets.worldNotes` | `WorldSummarySection`；收起显示一行截断摘要，展开最多 2–4 行 + “查看完整” |
| 角色（SummarySection） | 主角与配角的叙事摘要，区别于角色矩阵 | 从 `story_bible.md` 取“主角 / 配角”章节；因此截图中会出现第二个“角色”卡 | `project.protagonist`、`assets.characters`、角色资产 | 名称改为 **“人物摘要”**，避免与“角色状态”重名；收起显示主角名/人数，展开显示主角与主要配角摘要 |

**实施规则：** 主面板必须保留以上内容的“摘要线索”，不能把卡片做成只有标题的空容器；同时，主面板的展开内容应被严格限量，完整正文一律进入详情视图。

当前项目右栏虽然能力更全，但同时放入了 `书籍信息 / 章节 / 章节详情 / 大纲与章节计划 / 设定资产 / 写作上下文 / 任务日志 / 发布记录 / 设定 / 上下文预览` 等至少 10 个同级 section。结果是：

- 用户必须连续滚动，才能找到当前章节、角色或世界观；常用上下文被低频管理能力淹没。
- “章节详情”“大纲”“设定资产”包含大量按钮、编辑操作和长列表，不再是轻量上下文面板。
- `写作上下文` 已在 Composer 的“默认写作偏好 / 本章高级选项”中具备更合适的入口，却仍在右栏重复出现。
- `任务日志` 与新聊天任务卡重复；`上下文预览` 直接暴露大段 Prompt，属于调试/诊断而非普通创作信息。
- 一个过大的 `NovelBookPanel.tsx` 同时承担上下文展示、章节编辑、审稿、版本对比、资产管理、发布和任务恢复，继续迭代会让右栏再次膨胀。

### 完成后的体验

1. 右栏第一屏在常见桌面高度内只呈现 **章节、角色状态、核心文件、世界观** 四类主信息；最多额外显示一个很薄的进度摘要。
2. 默认不展示长正文、大量按钮、任务日志、发布记录、Prompt 原文或完整资产库。
3. 点击项目只做两件事之一：切换当前章节，或打开侧栏的“详情阅读/编辑视图”；不在同一栏无限展开嵌套管理界面。
4. 所有现有能力仍可访问，但低频能力收进 `更多工作区` 抽屉/菜单或独立 Dialog。
5. 右栏在窄屏变为可关闭的抽屉；桌面端可调整宽度，并保留用户展开状态。

## 2. 目标信息架构

### 2.1 主面板（默认，创作时常驻）

```text
┌─ 当前书籍 · 已生成 12 / 120 章 ──────────────────┐
│  （仅一行进度摘要；有运行任务时显示轻量状态）       │
├────────────────────────────────────────────────┤
│ ▾ 章节                                            │
│   ● 12 雨夜来信                         2,860 字  │
│   ○ 13 失踪的钥匙                        计划中    │
│   …（可滚动，点击打开章节详情）                    │
├────────────────────────────────────────────────┤
│ ▸ 角色状态                                        │
├────────────────────────────────────────────────┤
│ ▸ 核心文件                                        │
├────────────────────────────────────────────────┤
│ ▸ 世界观                                          │
├────────────────────────────────────────────────┤
│                         [更多工作区 ···]           │
└────────────────────────────────────────────────┘
```

| 区域 | 默认状态 | 显示内容 | 点击后的行为 |
| --- | --- | --- | --- |
| 当前书籍摘要 | 始终显示，高度 ≤ 44px | 书名、已生成/目标章节、当前运行状态 | 不展开；点击书名可定位书籍信息 |
| 章节 | 默认展开 | 收起：章节数量、当前章；展开：章节号、标题、状态、字数，列表最大高度约 220px | 选择当前章节；“查看全部/编辑”进入章节详情视图 |
| 角色状态 | 默认折叠 | 收起：角色数量/当前章相关角色名；展开：最多 4 个角色的名称、定位、当前状态 | 点击角色进入角色/资产详情视图 |
| 核心文件 | 默认折叠 | 收起：已加载文件数量；展开：世界观设定、卷纲、叙事规则、状态卡、伏笔池等链接 | 在同一 right-panel 切换为 Artifact View，提供返回与编辑 |
| 世界观 | 默认折叠 | 收起：首行截断摘要；展开：最多 2–4 行故事/世界观摘要 | “查看完整”进入 Artifact View；不得直接塞入全量 Markdown |
| 人物摘要 | 默认折叠 | 收起：主角名/主要配角数；展开：主角与主要配角的叙事摘要 | “查看完整”进入角色矩阵或故事圣经详情 |
| 更多工作区 | 始终在底部 | 大纲、资产库、审稿历史、任务恢复、发布记录、诊断 | 打开抽屉/菜单；不是第六个长卡片 |

### 2.2 详情视图（替代主面板，不与主面板叠加）

对齐 InkOS `ArtifactView` 的交互，新增 `BookContextDetailView`：

- 顶部：`← 返回`、标题、可选编辑按钮。
- 内容区：一个对象的全文/编辑器，例如章节、世界观、角色矩阵、伏笔池或大纲。
- 底部/更多菜单：版本对比、审稿问题、导出、删除等与该对象有关的低频操作。
- 关闭或返回后恢复主面板上原有的展开状态和滚动位置。

**禁止**：在主面板同时展开章节全文、章节版本对比、大纲节点编辑器、资产库和任务日志。

### 2.3 低频能力的新归属

| 当前 section / 功能 | 新入口 | 原因 |
| --- | --- | --- |
| 书籍信息的大型进度块 | 顶部单行摘要；完整统计在“更多工作区 → 书籍统计” | 创作时只需了解进度，不需一整张卡片 |
| 章节详情、正文编辑、审稿、版本对比 | 点击章节后的详情视图 | 属于对象级深度操作 |
| 大纲与章节计划 | 核心文件的“卷纲/章节计划”或更多工作区 | 大纲是重要资产，但不应一直展示编辑按钮 |
| 设定资产、冲突检测、待确认资产增量 | 更多工作区 → 资产库；右栏角色/世界观只展示摘要和异常徽标 | 资产库是管理界面，非主工作台常驻内容 |
| 写作上下文 | Composer 的“编辑默认写作偏好 / 本章高级选项” | 已有专用入口；右栏重复会产生两套心智模型 |
| 任务日志与断点继续 | 聊天任务卡；更多工作区 → 任务中心 | 过程应在对话流可见，历史恢复是低频能力 |
| 发布记录 | 更多工作区 → 发布与导出 | 和本章创作无直接关系 |
| 设定（世界观/卷纲/状态卡/角色矩阵） | 合并进“核心文件” | 避免与“设定资产”重复 |
| 上下文预览（完整 Prompt） | 更多工作区 → Prompt 诊断，仅开发/高级用户可见 | 不应在普通写作面板暴露长 Prompt |

## 3. 当前与目标的组件映射

| 当前文件 / 责任 | 目标组件 | 迁移要求 |
| --- | --- | --- |
| `components/NovelBookPanel.tsx` | `components/right-panel/BookContextPanel.tsx` | 只做主面板编排、当前详情路由和轻量 action；目标 < 500 行。 |
| `NovelBookPanel.tsx` 的章节卡、章节详情、编辑/版本/审稿 | `right-panel/ChaptersSection.tsx`、`right-panel/ChapterDetailView.tsx` | 列表保持紧凑；所有编辑/对比进入 detail view。 |
| `NovelBookPanel.tsx` 的大纲/设定/资产代码 | `right-panel/CoreFilesSection.tsx`、`right-panel/WorkspaceMoreMenu.tsx`、复用现有 Dialog | 不复制资产逻辑；先搬迁 UI 入口。 |
| `NovelBookPanel.tsx` 的写作上下文 | 删除右栏展示 | 复用 `components/writing/WriteChapterOptionsSheet.tsx`。 |
| `NovelBookPanel.tsx` 的任务/发布/Prompt 预览 | `right-panel/WorkspaceMoreMenu.tsx` 或独立 Dialog | 聊天区任务卡为过程唯一主展示。 |
| `components/sidebar/CollapsibleSection.tsx` | `right-panel/SidebarCard.tsx` / 改造现有组件 | 统一为 InkOS 式紧凑卡片；保留 localStorage 展开状态。 |
| `components/NovelStudio.tsx` | 仅传 `activeBook/project/selection` 与 callbacks | 不在此处添加右栏业务状态；详情状态放 `BookContextPanel` 或 store。 |

## 5. 约束与验证

- 不改 IndexedDB schema，不迁移已有小说、章节、资产或任务数据。
- 不删除高级能力；本次改版是“入口降噪”，不是“功能删减”。
- 不把任务过程从聊天任务卡搬回右栏。
- 不在 `NovelStudio.tsx` 中继续增加右栏业务代码。
- 迁移每一批后都执行：

```bash
source ~/.nvm/nvm.sh && nvm use 22 >/dev/null && pnpm --filter web run check-types
source ~/.nvm/nvm.sh && nvm use 22 >/dev/null && pnpm --filter web run lint
pnpm --filter web run test
```

手工验证至少覆盖：选择章节、进入/返回详情、编辑默认写作偏好、打开资产库、继续暂停任务、窄屏打开/关闭右栏，以及刷新后恢复展开状态。
