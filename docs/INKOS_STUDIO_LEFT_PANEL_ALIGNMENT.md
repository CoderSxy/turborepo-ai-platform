# InkOS Studio 左侧栏对齐改版说明（书籍 / 工具-普通聊天）

> 范围：只改造 AI 小说创作工作台左侧栏中的 **书籍** 与 **工具 - 普通聊天** 两部分。
>
> 不在范围：小说正文生成流程、Agent 行为、编辑区、右侧上下文面板、其他工具入口、书籍数据结构及服务端接口。

## 1. 改版目标

将当前“书籍管理面板”收敛为 InkOS Studio 式的轻量树状导航：用户首先看到书籍；只在需要时展开该书的普通聊天会话；改名、删除、归档等低频管理行为不再占据默认视图。

目标体验：

```text
书籍                                      + 新建书籍
›  📁 旧日秘密
⌄  📁 长夜行
      小说名《长夜行》……                       11 个月
   +  新建会话

工具
⌄  💬 普通聊天
      帮我整理人物关系……                         刚刚
   +  新建会话
```

核心原则：

1. **浏览优先**：默认只展示书名和展开状态，不让元信息、管理按钮打断扫描。
2. **同一心智模型**：书籍内会话与“工具 - 普通聊天”会话使用一致的树节点、选中态、更多菜单与新建入口。
3. **渐进披露**：搜索、归档、批量操作、改名、删除和排序只在用户主动进入相应入口后出现。
4. **行为兼容**：保留当前书籍、会话、归档、排序及快捷键能力；本次是信息架构与交互层级改造，不迁移、不丢失已有数据。

## 2. 现状与 InkOS 对齐差异

| 项目 | 当前项目左栏 | InkOS Studio 左栏 | 本次对齐要求 |
| --- | --- | --- | --- |
| 书籍默认信息 | 标题、题材/设定、会话数、选择框、五个操作按钮同时出现 | 仅折叠箭头、文件夹图标、书名 | 默认书籍节点仅保留展开箭头、图标和书名 |
| 会话可见性 | 仅活动书展开，但卡片结构较重 | 任意书可独立展开，展开时才加载/展示会话 | 使用 `expandedBookIds` 管理展开状态；活动书自动确保展开 |
| 书籍操作 | 上移、下移、改名、归档、删除常驻 | 默认不展示书籍管理按钮 | 收入书籍节点悬停 `…` 菜单；危险操作需二次确认 |
| 会话操作 | 改、删文字按钮常驻 | 悬停显示 `…`，菜单中改名/删除 | 统一改为悬停更多菜单；触屏和键盘仍可触达 |
| 搜索与归档 | 搜索框、筛选胶囊、快捷键提示常驻 | 书籍区保持干净 | 置于书籍标题行的“搜索/更多”入口；默认隐藏，展开后保留现有搜索与归档能力 |
| 批量管理 | 选择框、全选、批量归档/删除贯穿日常浏览 | 不占日常导航空间 | 移到“管理书籍”模式/弹层；只有显式进入后展示复选框和批量操作栏 |
| 书籍排序 | 上下箭头常驻 | 不干扰浏览 | 移到书籍 `…` 菜单的“上移/下移”，或“管理书籍”模式中的拖拽排序 |
| 空状态 | 文案强调管理、归档和导出 | 简洁地提示创建 | 只显示“还没有书籍”与“新建书籍”主操作 |
| 普通聊天 | 需与书籍会话分开理解或没有同款树结构 | 工具下的普通聊天也是可折叠会话树 | 与书籍会话使用同一 `SessionTreeItem`，保持独立的无书籍会话集合 |

## 3. 目标信息架构与交互规范

### 3.1 书籍区

```text
书籍                         [+ 新建书籍] [⌕] [⋯]
├─ ›  📁 旧日秘密
├─ ⌄  📁 长夜行                         [⋯]  ← 仅 hover/focus
│     ├─ 小说名《长夜行》……                 11 个月  [⋯]
│     ├─ 新的创作会话                       24 天    [⋯]
│     └─ + 新建会话
└─ ›  📁 雨夜来信
```

- 点击书籍行的箭头或行主体：仅展开/收起；不得意外创建、删除或切换会话。
- 点击书名（或双击书籍行，二选一并全局一致）：切换该书为当前书籍；若该书有活动会话则进入对应会话，若无则打开该书默认创作视图。
- 当前书籍为轻量文字/背景高亮，不使用大卡片边框。
- 支持同时展开多本书；首次展开时才加载该书会话，后续使用缓存。切换到某书时自动展开，避免“已进入但左栏找不到位置”。
- 会话节点显示：单行截断标题 + 相对时间；流式生成时以小型 loading 状态替代时间。
- 当前会话使用单行背景高亮；不要重复展示会话摘要、会话数或大段元数据。
- “+ 新建会话”始终位于已展开书籍会话列表底部；创建后立即选中并进入新草稿会话，发送首条消息时再持久化（沿用当前草稿策略）。

### 3.2 工具 - 普通聊天

```text
工具
⌄  💬 普通聊天
      帮我整理人物关系……                    刚刚  [⋯]
      新会话                                  2 小时 [⋯]
   +  新建会话
```

- “普通聊天”是工具区的一级可折叠节点；点击节点标题进入普通聊天页，同时切换展开/收起。
- 普通聊天会话使用与书籍会话完全一致的 `SessionTreeItem`：标题推导、相对时间、流式状态、选中态、改名/删除菜单一致。
- 新建普通聊天会话立即进入空草稿；与任何书籍无关联，不得写入书籍会话集合。
- 打开普通聊天时自动展开并按需加载无书籍会话列表；不能因收起/展开反复请求已缓存的数据。

### 3.3 低频管理入口

| 入口 | 内容 | 规则 |
| --- | --- | --- |
| 书籍节点 `…` | 重命名、归档/还原、上移、下移、删除 | 仅 hover、focus-visible 或触屏点击后显示；删除需确认 |
| 会话节点 `…` | 重命名、删除 | 仅 hover、focus-visible 或触屏点击后显示；删除需确认 |
| 书籍标题行 `⌕` | 搜索书名、题材、设定 | 点击后展开紧凑搜索行；`Esc` 清空并收起 |
| 书籍标题行 `…` | 已归档书籍、管理书籍 | “已归档书籍”默认独立查看；“管理书籍”才进入批量选择/排序模式 |
| 管理书籍模式 | 多选、全选、批量归档/还原/删除、排序 | 明确显示“完成管理”；退出后不保留复选框和批量操作栏 |

补充约束：

- 日常左栏禁止同时出现搜索框、归档筛选、全选、快捷键提示、复选框、排序按钮、改名/删除按钮。
- `…` 不应改变节点宽度或使列表跳动；只在相应节点的 hover/focus 可见。
- 所有 icon-only 按钮需要 `aria-label`、`title`、可见焦点样式，菜单可用键盘方向键、Enter 和 Esc 操作。

## 4. 实现设计（给 Cursor）

### L1：抽离树状结构，先保持现有数据与行为

涉及位置：

- `apps/web/features/studio/components/NovelBookList.tsx`
- `apps/web/features/studio/components/NovelStudio.tsx`
- `apps/web/features/studio/studio.module.css`

实施：

1. 将 `NovelBookList` 重构为 `BookTreeSidebar`（可保留原文件名以避免无意义迁移），拆出：
   - `BookTreeItem`
   - `SessionTreeItem`
   - `BookSidebarHeader`
2. 新增本地 `expandedBookIds: Set<string>`，不再以 `activeBookId === book.id` 作为唯一展开条件。
3. 将现有 `book.sessions` 渲染为轻量树节点；保留 `onBookSelect`、`onSessionSelect`、`onCreateSession` 的现有业务语义。
4. 创建新会话、选中书籍或选中会话时确保对应书籍处于展开状态。
5. 先不删除任何现有回调；仅把它们从默认界面移出，为 L2 的菜单/管理模式复用。

验收：截图中默认书籍区只出现树节点；已有书籍、会话的选择与新建不回归。

### L2：将管理能力转为渐进披露

实施：

1. 用现有项目组件或无障碍实现提供 `BookActionsMenu`、`SessionActionsMenu`；不要依赖鼠标 hover 才能完成操作。
2. 将 `onRenameBook`、`onArchiveBook`、`onDeleteBook`、`onMoveBook` 接入书籍菜单；菜单项按状态显示“归档”或“还原”，首尾书籍禁用相应排序项。
3. 将 `onRenameSession`、`onDeleteSession` 接入会话菜单。
4. 将搜索、已归档、全选和批量操作从默认 DOM 布局移走：
   - 搜索由标题行搜索按钮按需展开；
   - 归档书籍默认不与进行中书籍混排；
   - 批量操作仅在“管理书籍”模式出现。
5. 保留快捷键：`/` 聚焦搜索、`N` 新建书籍、`Esc` 依次关闭菜单/搜索/管理模式；不要在用户编辑文本框时拦截这些按键。

验收：对单书和单会话的完整管理能力仍可到达，但日常截图中不显示复选框或一串按钮。

### L3：对齐“工具 - 普通聊天”会话树

实施：

1. 明确普通聊天使用的会话来源与书籍会话区分（例如 `bookId === null` / 独立集合），不得混入当前书籍的 `sessions`。
2. 将普通聊天节点与会话列表复用 `SessionTreeItem`；统一标题回退规则：显式标题 → 第一条用户消息单行截断 → “新会话”。
3. 为普通聊天实现与书籍相同的展开状态、懒加载、草稿创建、选中态、流式状态、改名和删除确认。
4. 若当前工作台没有“工具 - 普通聊天”左栏节点，在不改变现有页面路由的前提下新增该节点；不新增其它工具，也不迁移小说生成会话。

验收：用户不看说明也能在书籍聊天和普通聊天之间区分归属，并以相同方式新建、切换和管理会话。

### L4：视觉、可访问性与回归测试

实施：

1. 调整 CSS 为紧凑行高、弱边界、单行选中背景；移除默认书籍卡片的大边框和元信息堆叠。
2. 窄屏时侧栏保持可滚动，菜单不得被裁切；长书名/会话标题必须截断而非撑宽布局。
3. 添加或更新组件测试，覆盖下节验收场景。
4. 运行项目既有 `check-types`、`lint` 和相关单测；不要以跳过类型检查来规避改动。

## 5. 数据与兼容性约束

1. 不修改书籍、会话、归档、排序的数据 schema；历史书籍和历史会话必须原样显示。
2. 归档、删除、重命名、排序必须继续走现有 action/store，避免左栏出现仅 UI 成功但刷新后丢失的乐观状态。
3. 书籍展开状态是 UI 偏好，可只保存在内存；无需为了该改版写入书籍数据。若持久化，须与旧数据缺字段兼容。
4. 切换书籍或普通聊天不应触发重复会话列表请求：仅首次展开、显式刷新或数据版本变化时刷新。
5. 删除当前会话/当前书籍后，必须复用现有安全回退选择逻辑，不能留下无效的 `activeBookId` / `activeSessionId`。

## 6. 验收清单

- [x] 默认左栏的书籍区没有搜索框、全选、选择框、书籍摘要、会话数、上下移动按钮、改名/归档/删除文字按钮。
- [x] 每本书以“箭头 + 文件夹图标 + 书名”的单行树节点呈现；展开后才显示会话和“新建会话”。
- [x] 可同时展开多本书；当前书籍/会话切换后对应书籍保持可见且展开。
- [x] 会话仅展示标题和相对时间（流式时显示生成状态），长标题不会破坏布局。
- [x] 书籍与会话的改名、删除、归档/还原、排序和批量管理仍可从菜单或管理模式完成。
- [x] 删除行为都有确认；归档书籍默认不干扰进行中书籍列表，并可从“已归档书籍”入口恢复。
- [ ] “工具 - 普通聊天”具备同样的可折叠会话树、新建草稿、会话切换、重命名和删除体验，但与书籍会话数据隔离。
- [x] 鼠标、触屏、键盘均能访问折叠、更多菜单和全部操作；`Esc` 不会误清空正在编辑的输入内容。
- [x] `pnpm --filter web run check-types`、`pnpm --filter web run lint` 与相关组件测试通过。

## 7. 不做事项

- 不将左栏改造成右侧上下文面板，不复制 InkOS 的主题颜色或品牌外观。
- 不删除高级书籍管理能力，只改变其可见层级。
- 不把普通聊天与“AI 小说创作”的生成任务、章节生成会话或 Agent 执行日志混合。
- 不在本次改版中重写服务端会话模型、书籍模型或历史数据。
